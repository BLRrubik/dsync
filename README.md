# dsync — синхронизатор директорий

`dsync` — CLI-утилита на Go для одностороннней синхронизации директорий: приводит содержимое целевой директории (`dest`) в точное соответствие с исходной (`source`) по содержимому файлов (SHA-256), а не по имени/дате изменения.

## Возможности

- Рекурсивный обход обеих директорий и построение таблицы `путь → SHA-256 хэш` для каждого файла.
- Параллельное хэширование файлов (пул из 10 воркеров) — ускоряет обработку больших деревьев.
- Сравнение состояний источника и назначения по трём категориям:
  - **Копирование** — файлы, которые есть в источнике, но отсутствуют в назначении.
  - **Обновление** — файлы, которые есть в обеих директориях, но их содержимое отличается (хэш не совпадает).
  - **Удаление** — файлы, которые есть в назначении, но отсутствуют в источнике.
- Реальное выполнение операций: копирование (с автосозданием недостающих поддиректорий), перезапись при обновлении, удаление лишних файлов.
- Прогресс-бар (`github.com/schollz/progressbar/v3`) с общим числом операций (`toCopy + toUpdate + toDelete`), обновляется через `bar.Add(1)` после каждой операции.
- Цветной вывод (`github.com/fatih/color`) по типу операции:
  - 🟢 зелёный — `[КОПИРОВАНИЕ]`
  - 🟡 жёлтый — `[ОБНОВЛЕНИЕ]`
  - 🔴 красный — `[УДАЛЕНИЕ]`
- Итоговая сводка по завершении: `Скопировано: X, Обновлено: Y, Удалено: Z`.

## Установка и сборка

Требования: Go 1.26+.

```bash
git clone https://github.com/BLRrubik/dsync.git
cd dsync
go build -o bin/dsync .
```

Бинарник появится в `bin/dsync`.

Без сборки, напрямую через `go run`:

```bash
go run main.go <source> <dest>
```

## Примеры использования

```bash
./bin/dsync ./source ./backup
```

```
Синхронизация...
100% |███████████████████████████████████████| (21/21)

[КОПИРОВАНИЕ] a.txt
[ОБНОВЛЕНИЕ] b.txt
[УДАЛЕНИЕ] c.txt

Синхронизация завершена!
Скопировано: 12, Обновлено: 5, Удалено: 4
```

где:
- `<source>` — путь к исходной директории (эталон);
- `<dest>` — путь к целевой директории, которая будет приведена в соответствие с `<source>`.

**Внимание:** операция необратима — файлы в `<dest>`, отсутствующие в `<source>`, будут удалены безвозвратно.
